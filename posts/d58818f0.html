WebGL 学习笔记

发表于2024-12-08|更新于2026-11-15|学习
|字数总计:3.8k|阅读时长:14分钟

想做一些 CSS 和 Canvas 做不到的视觉效果，于是开始学 Shader。这篇记录我从零写片元着色器的过程：先搞懂它在渲染管线里的位置和 GLSL 的基本写法，再从 UV 坐标出发，一步步画出圆、模糊、发光和任意 SDF 图形，最后弄明白为什么平移、缩放的方向和直觉相反。文中所有效果图都是用文中的代码实际渲染出来的。

参考：WebGL Fundamentals、The Book of Shaders、Inigo Quilez 的 2D SDF 函数合集、掘金作者 alphardex 的 Shader 入门系列（学习路线主要参考它）

1. Shader 是什么

Shader（着色器）是跑在 GPU 上的小程序。和 CSS、SVG、Canvas 2D 比，它最大的不同是每个像素都会并行地执行一遍同一段代码，所以能做像素级、而且很重的计算。

技术擅长做不好的
CSS布局、简单的 transform 和过渡动画像素级的动态效果
SVG矢量图形、路径描边动画大量粒子、逐像素计算
Canvas 2D逐像素绘制、2D 粒子复杂 3D、像素很多时性能吃紧
WebGL + Shader2D/3D 都行，把计算交给 GPU 并行完成写起来更底层，调试不方便

这篇只讲片元着色器。做 2D 效果时，最常见的做法是画一个铺满整个画布的矩形，然后把所有效果都写在片元着色器里：它会对画布上的每个像素问一遍“你应该是什么颜色”。

选 GLSL

几种主流的着色器语言：GLSL（OpenGL / WebGL）、HLSL（DirectX）、WGSL（WebGPU）。在浏览器里用 WebGL，就写 GLSL。

2. 第一个 Shader

最方便的练习环境是 Shadertoy：打开就能写，不用自己搭 WebGL 的那一堆初始化代码。它约定写一个 mainImage 函数：

  • fragCoord：当前像素的坐标，单位是像素，原点在左下角

分支要少用

GPU 是一组一组像素一起执行同一条指令的。同一组里如果有的像素走if、有的走else，两个分支都要执行一遍，再按条件取结果。所以写 Shader 时习惯用step、mix、clamp这些内置函数代替if，后面画圆时会看到怎么替换。

变量限定符

限定符作用
uniform由 JS 传进来、对所有顶点和像素都一样的值，比如画布大小、时间、鼠标位置
attribute每个顶点各自的数据，比如顶点位置，只能在顶点着色器里用（WebGL 1）
varying顶点着色器算好、传给片元着色器的值，光栅化时会在三角形内部自动插值（WebGL 1）
const编译期常量
  • WebGL 2 用的 GLSL ES 3.00 里，attribute改叫in，varying改成顶点着色器的out加片元着色器的in
  • iTime、iResolution、iMouse不是限定符，而是 Shadertoy 预先声明好的uniform变量

4. UV 坐标

fragCoord 的单位是像素，范围取决于画布有多大，换一个尺寸的画布，同样的代码效果就变了。所以几乎每个 Shader 的第一行都是把它归一化到0到1之间，得到的坐标叫 UV：

把坐标直接当颜色输出，是理解坐标分布最直观的方法：

uv.x从左边的0（黑）增加到右边的1（红），形成横向渐变。

uv.y从下往上增加，说明原点在左下角，这一点和网页里y轴向下的习惯相反。

四个角正好对应(0,0)黑、(1,0)红、(0,1)绿、(1,1)黄。

8. UV 变换

要移动、缩放、翻转图形，做法都是先变换UV坐标，再把变换后的坐标交给 SDF。这里有一个一开始很反直觉的地方。

平移：方向是反的

想把矩形往右上移，第一反应是给坐标加上偏移：

结果矩形往左下跑了。原因是我们改的不是图形，而是每个像素“认为自己在哪”：

  • sdBox永远把矩形画在坐标原点
  • 加上(0.2, 0.4)后，画布中心的像素认为自己在(0.2, 0.4)；真正得到坐标(0, 0)的，是中心左下方(0.2, 0.4)处的那个像素
  • 所以矩形出现在了左下方

学到的几件事

  • 思路的转变：写片元着色器不是“在某个位置画一个东西”，而是写一个函数，回答“这个像素应该是什么颜色”，GPU 会对每个像素并行地问一遍
  • 固定开头：归一化、居中、修正宽高比这三行，几乎每个 2D Shader 都要写
  • 形状 = 距离 + 阈值：用 SDF 算出距离，再用step得到硬边、smoothstep得到抗锯齿或模糊、倒数得到发光。换形状只需要换 SDF
  • 变换的是坐标，不是图形：所以平移、缩放、旋转都要做反方向的运算，才能得到想要的效果。先想清楚“现在是哪个像素拿到了原点”，方向就不会弄错
