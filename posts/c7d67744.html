1. CSS 题目

1.1 画等腰直角三角形

  • 美团前端一面题：参考链接

  • 第一种方法：使用border

    • 宽高为0时，元素只剩四条边框，每条边框都是一个三角形；只设置两条相邻的边框，一条上色、一条透明，就得到直角三角形
  • 第二种方法：使用linear-gradient
    • 沿对角线做渐变，一半有颜色、一半透明，颜色在50%处直接切换
  • 第三种方法：使用clip-path
    • 直接用多边形把正方形裁成三角形，三个点就是三角形的三个顶点

1.2 不定宽高水平垂直居中

  • 第一种方法：使用Flexbox
  • 第二种方法：使用Grid
  • 第三种方法：绝对定位 + transform
    • top、left的50%是相对父元素的，把子元素的左上角移到中心；translate的-50%是相对子元素自身的，再往回移一半，所以不需要知道子元素的宽高

1.3 正方形子元素

  • 字节跳动一面题：父元素宽高不固定、会随窗口变化，子元素必须始终保持正方形（只能用CSS）
    • 解决方案：子元素用百分比宽度，再用aspect-ratio: 1 / 1保持正方形比例
  • 不支持aspect-ratio的老浏览器，可以利用padding的百分比是相对父元素宽度计算的这一点

1.4 position 定位

  • position: static（默认）：元素按正常文档流排列，top、right、bottom、left和z-index都不生效

  • position: relative（相对定位）：相对元素自身原本的位置偏移，原来占的空间仍然保留

  • position: absolute（绝对定位）：脱离文档流，相对最近的非static祖先元素定位；如果没有这样的祖先，就相对初始包含块（大小等于视口）定位

  • position: fixed（固定定位）：相对视口定位，页面滚动时位置不变

    • 例外：如果某个祖先元素设置了transform、filter或perspective，fixed会改成相对这个祖先定位

  • position: sticky（粘性定位）：结合了relative和fixed。滚动到阈值之前表现为relative，之后固定在最近的滚动容器里

    • 必须指定top、bottom、left、right中的至少一个，否则效果和relative一样
    • 它粘在最近的滚动祖先上；如果中间某个祖先设置了overflow: hidden、auto或scroll，它就只会在那个祖先里粘住，看起来像失效
    • 只能在父元素的范围内粘住，父元素滚出视口后它也会跟着离开

1.5 盒模型

盒模型分为W3C标准盒模型和IE盒模型（怪异盒模型）

  • 标准盒模型：元素占据的总宽度 = width + padding(左右) + border(左右) + margin(左右)
  • IE盒模型：元素占据的总宽度 = width + margin(左右)，此时width已经包含了padding和border

box-sizing: content-box使用标准盒模型，也是默认值
box-sizing: border-box使用IE盒模型，实际开发中更常用，因为改padding不会撑大元素

  • JS获取元素的宽和高
    • window.getComputedStyle(dom).width：最终生效的样式值，返回带单位的字符串，比如"100px"
    • dom.getBoundingClientRect().width：渲染后的实际尺寸（包含transform缩放），还能拿到相对视口的位置
    • dom.offsetWidth：内容 + padding + border，不含margin，结果会取整

1.6 CSS 实现扇形

  • 方法一：border-radius画四分之一圆，得到90°扇形
  • 方法二：border三角形 + border-radius，原理和画三角形一样，只是把三角形的外边变成圆弧
  • 方法三：conic-gradient，可以画任意角度

1.7 BFC

  • BFC（Block Formatting Context，块级格式化上下文）是一块独立的渲染区域，里面元素的布局不会影响外面

  • 触发BFC的常见方式

    • display: flow-root（专门用来创建BFC，没有副作用，推荐）
    • overflow不为visible，比如overflow: hidden
    • float不为none
    • position: absolute或fixed
    • display: inline-block、table-cell，或者flex、grid容器的直接子元素

  • BFC能解决的问题

    • 清除浮动：父元素只有浮动子元素时高度会塌陷，父元素触发BFC后会把浮动元素算进高度
    • 防止外边距合并：相邻两个块的上下margin会合并，把其中一个放进新的BFC就不会合并
    • 防止被浮动元素覆盖：BFC区域不会和浮动元素重叠，可以用来做两栏自适应布局

2. JS 题目

2.1 var 与循环

  • 字节跳动一面题：下面的循环输出什么，循环结束后i的值是多少
  • 输出0 1 2 3 4，循环结束后i的值是5
  • var是函数作用域，不受块作用域限制，所以循环结束后i仍然存在并且可以访问
  • 输出5 5 5 5 5
  • 所有回调共享同一个i。setTimeout的回调在1秒后才执行，那时循环早已结束，i已经是5
  • 解决方案：改用let，每次迭代都会创建一个新的i；或者用闭包把当前的值保存下来

2.2 手写倒计时

  • 美团一面题：手写一个倒计时函数，依次输出5 4 3 2 1，每隔一分钟输出一个值

  • 方法一：使用setInterval

    • setInterval按固定间隔反复执行，直到手动清除
  • 方法二：使用Generator函数
    • Generator可以用yield暂停和恢复执行，配合setTimeout实现倒计时

2.3 防抖和节流

  • 实际项目里可以直接用lodash的debounce和throttle，面试一般要求手写

  • 防抖Debounce

    • 事件触发n毫秒后才执行回调；如果这段时间内事件又被触发，就重新计时
    • 适合搜索框输入联想、窗口resize结束后再计算，或者防止按钮被连续点击发出多次请求

防抖分为非立即执行版（上面这种，停下来之后才执行）和立即执行版（第一次触发马上执行，之后一段时间内不再执行），根据场景选择

  • 节流Throttle
    • 一段时间内只执行一次，即使重复触发也只有一次生效
    • 适合滚动scroll、鼠标移动mousemove这类高频事件，降低处理频率

时间戳版在每个时间段开始时执行（第一次触发立即执行），定时器版在每个时间段结束时执行（停止触发后还会再执行一次）

2.4 undefined 与 null 的区别

  • undefined表示”缺少值”：变量声明了但还没赋值、函数没有返回值、访问对象不存在的属性，得到的都是undefined
  • null表示”没有对象”：一般是开发者主动赋值，表示这里本来就不应该有值

2.5 浅拷贝和深拷贝

  • 浅拷贝
    • 创建一个新对象，把原对象的每个属性值复制过去
    • 属性是基本类型就复制值；属性是引用类型就只复制内存地址，所以修改其中一个对象里的引用类型属性，另一个也会跟着变
    • 常用写法：{ ...obj }、Object.assign({}, obj)、arr.slice()
  • 深拷贝
    • 在堆内存里开辟新的空间，把整个对象完整复制一份，修改新对象不会影响原对象
    • 现代浏览器和Node.js 17+可以直接用structuredClone(obj)，支持循环引用、Date、Map、Set，但不能拷贝函数
    • JSON.parse(JSON.stringify(obj))最简单，但会丢失undefined、函数、Symbol，Date会变成字符串，遇到循环引用会报错

2.6 函数柯里化

  • 柯里化是把一个接收多个参数的函数，转换成一系列只接收部分参数的函数，参数凑够了才真正执行

柯里化的价值在于参数复用和延迟执行：先固定一部分参数，得到一个更专用的函数。本质上是降低通用性，提高适用性

  • 参数定长的柯里化
    • 原函数fn接收三个参数a, b, c，那么fn最多被柯里化三次
  • 参数不定长的柯里化
    • 参数个数不固定时，没法知道什么时候该执行，所以每次调用都只能返回一个函数
    • 做法是重写返回函数的toString，当它被隐式转换成原始值时（比如+add(1)(2)或者模板字符串）才真正计算

2.7 数组扁平化

实现一个flatten函数，把多级嵌套数组[1, [2, [3, [4, 5]]], 6]扁平化，输出[1, 2, 3, 4, 5, 6]

  • ES2019的flat
    • flat(depth)按指定深度展开数组，传Infinity可以展开任意深度

⭐ 直接用内置方法最快，但面试官一般还想看你手写

  • 循环 + 递归
    • 遍历每一项，用Array.isArray判断是否是数组
    • 是数组就递归展开再拼接，不是数组就直接push

⭐⭐⭐ 用递归实现扁平化，但没法控制展开的层数

  • 增加参数控制扁平化深度
    • 相当于手写flat()

⭐⭐⭐⭐ 用递归实现扁平化，并且可以通过参数控制层数

  • while循环 + some方法
    • 用some判断数组里是否还有数组，有就用扩展运算符...展开一层，再用concat合并，直到没有嵌套为止

⭐⭐⭐⭐ 用while循环代替递归，巧用some判断是否还有嵌套

2.8 typeof 判断

  • typeof null是"object"：历史遗留问题
  • typeof NaN是"number"：NaN本身就是一个特殊的数值
  • typeof Function.prototype是"function"
  • 要准确判断类型，可以用Object.prototype.toString.call(value)，比如数组返回"[object Array]"

2.9 事件委托优化

  • 字节一面题

比如要做一个Event Tracking System，记录用户在网站里点击了哪些按钮。如果按钮很多，每个都绑定点击事件性能很差，怎么优化？

  • 把事件绑定到父元素
    • 不给每个子元素单独绑定，而是绑定在公共的父元素上，利用事件冒泡统一处理
  • 判断目标元素
    • 用event.target判断实际触发事件的是哪个子元素；子元素内部还有嵌套标签时，用event.target.closest('.child')找到真正的目标

事件委托特别适合元素很多或者动态生成的场景，比如列表、表格行；新增的子元素不需要再单独绑定事件

3. 网络安全

3.1 跨站脚本攻击 XSS

  • XSS（Cross-Site Scripting）是攻击者把恶意脚本注入网页，用户打开页面时脚本在用户浏览器里执行，可以窃取Cookie、冒充用户操作
  • 常见类型
    • 存储型：恶意脚本被存进数据库（比如评论），所有访问的用户都会中招
    • 反射型：恶意脚本放在URL参数里，服务端原样拼进页面返回
    • DOM型：前端JS直接把不可信数据写进DOM，比如innerHTML
  • 防御
    • 输出时转义：把<、>、&、"、'等字符转成HTML实体；React、Vue默认会转义插值
    • 避免直接插入HTML：慎用innerHTML、v-html、dangerouslySetInnerHTML，必须用时先用DOMPurify这类库过滤
    • 设置Content-Security-Policy（CSP），限制页面能加载和执行哪些脚本
    • 敏感Cookie设置HttpOnly，让JS读不到

3.2 跨站请求伪造 CSRF

  • CSRF（Cross-Site Request Forgery）是攻击者诱导已登录的用户访问恶意页面，利用浏览器会自动带上Cookie的特点，以用户身份向目标网站发请求，比如转账、改密码
  • 防御的核心是确认请求确实是用户在本站主动发起的
    • CSRF Token：服务端生成随机令牌放进页面或表单，请求时带上，服务端校验；第三方网站拿不到这个令牌
    • SameSite Cookie：设置SameSite=Lax或Strict，跨站请求不带Cookie；Chrome对没有设置SameSite的Cookie默认按Lax处理
    • 校验Origin或Referer请求头，拒绝来自其他域名的请求
    • 敏感操作要求二次验证，比如重新输入密码或验证码

4. 网络协议

4.1 网络七层模型与四层模型

  • OSI七层模型（Open Systems Interconnection）是一个理论标准，不是具体实现
  • TCP/IP四层模型是实际使用的模型，由七层模型简化合并而来；传输层和网络层被完整保留，所以网络里最核心的就是这两层
OSI 七层作用例子TCP/IP 四层
应用层为应用程序提供网络服务HTTP、DNS、FTP、SMTP应用层
表示层数据格式转换、编码、压缩、加密JPEG、ASCII、TLS 的加密应用层
会话层建立、管理和断开应用之间的会话RPC、会话恢复应用层
传输层端到端传输，按端口区分不同进程TCP、UDP传输层
网络层IP 寻址和路由，把数据送到目标主机IP、ICMP网络层（网际层）
数据链路层在相邻节点之间传输数据帧，用 MAC 地址标识设备以太网、交换机网络接口层
物理层传输比特流网线、光纤、网卡标准网络接口层

越往下越接近硬件，越往上越接近软件。发送数据时从上往下逐层加头部封装，接收时从下往上逐层解开

4.2 HTTP 和 HTTPS

  • HTTP（HyperText Transfer Protocol）是应用层协议，定义客户端和服务器之间如何请求和响应。HTTP/1.1和HTTP/2基于TCP，HTTP/3基于QUIC（UDP）。HTTP本身是无状态的，登录状态要靠Cookie、Token来维持
  • HTTPS是HTTP的安全版：HTTPS = HTTP + TLS，在HTTP和TCP之间加了一层TLS。SSL是TLS的前身，已经废弃，但习惯上仍然叫”SSL证书”
  • HTTPS主要解决三个问题
    • 加密：数据在传输过程中被截获也看不懂
    • 完整性：数据被篡改能被发现
    • 身份认证：通过证书确认访问的确实是这个网站，防止中间人冒充
对比HTTPHTTPS
传输方式明文TLS 加密
默认端口80443
证书不需要需要 CA 签发的证书；Let’s Encrypt 等机构提供免费证书，大部分托管平台会自动配置
性能无额外开销多一次 TLS 握手；TLS 1.3 只需 1 个往返，基本可以忽略

4.3 HTTP/1.x、HTTP/2 和 HTTP/3 的区别

  • HTTP/2使用二进制分帧，HTTP/1.x是文本格式

    • 二进制传输的单位是帧（frame），多个帧组成一个流（stream），每个流有自己的流ID
    • 好处是解析更快、更不容易出错

  • HTTP/2支持多路复用

    • 同一个TCP连接上可以同时传输多个请求和响应，靠流ID区分各自属于哪个请求
    • HTTP/1.1同一个连接上只能一个请求接一个请求，浏览器只好对每个域名开 6 个左右的连接并发请求

  • HTTP/2头部压缩

    • 使用专门的HPACK算法（不是gzip）。客户端和服务器各自维护一张头部字段表，重复出现的字段只需要发送表里的索引，大幅减少重复头部（比如Cookie、User-Agent）的体积

  • HTTP/2服务器推送

    • 服务器可以在客户端请求之前主动推送资源，比如请求HTML时顺便推送CSS
    • 实际效果不好，Chrome从106版开始已经默认禁用；现在一般用<link rel="preload">或103 Early Hints代替

  • HTTP/3

    • HTTP/2的多路复用仍然跑在一个TCP连接上，一旦丢包，整个连接上的所有流都要等重传，这叫TCP队头阻塞
    • HTTP/3改用基于UDP的QUIC协议，每个流独立重传，一个流丢包不影响其他流；建立连接也更快，还支持切换网络（比如Wi-Fi换成4G）时不断开

4.4 HTTP 请求方式

HTTP常用的请求方式有9种，其中GET和POST最常用

  • GET：获取资源，不应该产生副作用，参数放在URL里
  • POST：提交数据，比如提交表单、上传文件，数据放在请求体里；可能创建新资源或修改已有资源
  • PUT：用请求体整体替换指定资源
  • PATCH：对资源做部分修改
  • DELETE：删除指定资源
  • HEAD：和GET一样，但响应只返回头部不返回内容，可以用来检查资源是否存在、获取文件大小
  • OPTIONS：查询服务器对某个资源支持哪些请求方法；跨域时浏览器发的预检请求就是OPTIONS
  • TRACE：回显服务器收到的请求，用于诊断，出于安全考虑通常被禁用
  • CONNECT：让代理服务器建立隧道，比如通过代理访问HTTPS网站

幂等：同一个请求执行一次和执行多次效果相同。GET、HEAD、PUT、DELETE、OPTIONS是幂等的，POST和PATCH不是

4.5 TCP 三次握手与四次挥手

  • 三次握手（建立连接）

  • 为什么是三次，不是两次

    • 双方都要确认”自己能发、对方能收”和”对方能发、自己能收”，三次正好让双方都确认了这两点
    • 防止已经失效的旧连接请求：如果一个很早发出的SYN滞留在网络里，后来才到达服务端，两次握手的话服务端会直接建立一个没人用的连接，白白占用资源；三次握手时客户端不会回应这个旧请求，连接就建不起来

  • 四次挥手（断开连接）

  • 为什么是四次：TCP是全双工的，两个方向要分别关闭。服务端收到FIN时可能还有数据没发完，所以ACK和FIN要分开发
  • 为什么客户端最后要等2MSL（TIME_WAIT）：保证最后一个ACK能到达服务端，如果丢了服务端会重发FIN；同时让这个连接残留的旧报文在网络中全部消失，不影响之后用同一端口建立的新连接

5. 缓存

5.1 强缓存与协商缓存

  • 为了减少请求次数、加快加载速度，浏览器会缓存图片、CSS、JS等资源。浏览器缓存分为强缓存和协商缓存，参考：链接

  • 强缓存

    • 浏览器判断本地缓存还在有效期内，就直接使用，不发请求到服务器
    • 服务器在响应头里设置Cache-Control: max-age=31536000，单位是秒，这里是一年，一年内浏览器都直接用缓存

  • 命中强缓存时，DevTools的Network面板里状态码显示为200 (from memory cache)或200 (from disk cache)；缓存过期后再请求，就只显示200

    • 一般来说，较大的资源缓存在disk cache，较小的资源缓存在memory cache；内存缓存读取更快，但关闭标签页就没了

  • 除了Cache-Control，还可以用Expires。Expires是HTTP/1.0的字段，值是一个具体的过期时间点

  • Expires对比的是客户端本地时间，而用户可以修改本地时间，所以会有误差。HTTP/1.1引入了Cache-Control来解决这个问题

Cache-Control的优先级高于Expires，两者同时存在时只看Cache-Control

  • Cache-Control的常用值

    • max-age=秒数：缓存有效期
    • no-cache：可以缓存，但每次使用前都必须向服务器确认（也就是走协商缓存），不是”不缓存”
    • no-store：完全不缓存
    • public、private：是否允许CDN等中间代理缓存

  • 协商缓存

    • 强缓存由浏览器自己判断；协商缓存每次都要发请求问服务器，由服务器决定能不能用缓存
    • 第一次请求时，服务器在响应头里返回ETag（资源的唯一标识，内容变了它就变）。再次请求时，浏览器在请求头里带上If-None-Match，值就是上次的ETag，服务器拿它和最新的ETag比较

没有变化：返回304 Not Modified，不带响应体，浏览器继续用缓存
有变化：返回200和最新的资源

  • 除了ETag，还有HTTP/1.0的Last-Modified：服务器返回文件的最后修改时间，浏览器下次请求时用If-Modified-Since带回去，服务器比较时间是否变化

  • ETag的优先级高于Last-Modified，也更精确

    • Last-Modified只精确到秒，一秒内多次修改识别不出来
    • 文件内容没变但修改时间变了（比如重新部署），Last-Modified会让浏览器重新下载，而ETag不会

强缓存优先于协商缓存：强缓存在有效期内就直接用，不会发请求，也就不会走协商缓存

  • 实际项目的常见做法
    • HTML设置no-cache，每次都向服务器确认，保证能拿到最新版本
    • 打包出来带内容哈希的文件（比如app.3f2a1c.js）设置很长的max-age，内容一变文件名就变，不用担心缓存过期

6.2 格式化数字

  • 字节一面算法题：把1000000转成1,000,000，把1000000.12转成1,000,000.12，只能用JS

  • 注意：千分位只加在整数部分，小数部分不加逗号

  • 方案一：使用toLocaleString或Intl.NumberFormat

    • 要指定'en-US'，否则在德语等地区会用.作分隔符
    • 默认最多保留3位小数，需要用maximumFractionDigits放宽
  • 方案二：正则表达式
    • 只对整数部分做替换；如果对整个字符串替换，小数部分超过3位时也会被加上逗号，比如1234.5678会变成1,234.5,678
  • 方案三：手动实现
    • 从整数部分的末尾往前数，每3位插入一个逗号
