hireEZ 实习总结

发表于2025-02-26|更新于2026-11-15|工作
|字数总计:855|阅读时长:2分钟

我在 2022 年和 2024 年两次在 hireEZ（一家做 AI 招聘平台的公司）实习，主要做前端功能和内部效率工具。这篇按项目整理每段实习做了什么：遇到什么问题、怎么做的、结果如何。

2022 年实习

Jira 工单生成器

问题：BI team 每次要建一批工单，都是从 Excel 里手动复制粘贴到 Jira，而且工单之间有 parent / child 的层级关系，手动建既慢又容易出错。

做法

  • 用 React 做了一个工具页面，把要创建的工单渲染成树状结构，可以直观地看到层级关系
  • 员工信息来自 AWS Lambda 提供的接口，用来给工单分配负责人
  • 确认无误后，调用 Jira REST API 按层级批量创建 parent / child 工单

结果：替代了原来的手动流程，为 BI team 每周节省数小时的重复操作。

技术栈：React、AWS Lambda、Jira REST API

GA4 埋点与测试

问题：产品需要用户行为数据来支持产品决策和 UX 优化，同时要确保埋点数据是准确的，否则数据分析就没有意义。

做法

  • 在现有产品上接入 Google Analytics 4，追踪页面浏览、按钮点击、功能使用等用户行为
  • 用 Playwright 写端到端 UI 测试，模拟用户操作，验证每个埋点事件是否被正确触发和采集

结果：产品有了可用的用户行为数据，埋点也有自动化测试保证，后续改动不容易把埋点改坏。

技术栈：Google Analytics 4、Playwright

2024 年实习

Chrome 插件：候选人匹配

问题：候选人匹配功能原本只在 Web 端有，招聘人员在 LinkedIn、Greenhouse 上看候选人时，要切回 Web 端才能用。

做法

  • 用 content script 解析当前页面，从 Greenhouse 的 URL 和 LinkedIn 页面中提取候选人 ID
  • 同时支持单个候选人的 profile 页，和 LinkedIn My Network 页面上的批量匹配
  • 调用已有的后端 API，找出数据库中经历或技能相近的候选人
  • 用 React 和公司的组件库实现结果展示组件

结果：把 Web 端的匹配功能带到了插件里，招聘人员在浏览候选人时就能直接看到匹配结果。

技术栈：Chrome Extension、React、JavaScript、HTML、CSS

AWS Q Business 知识检索（技术调研）

问题：团队的文档和讨论分散在 Jira、Confluence 和 Slack 里，想评估能不能用 AWS Q Business 低代码地搭一个内部知识检索系统。

做法

  • 用 Q Business 的 connector 把 Jira、Confluence、Slack 接成数据源
  • 用 CloudFormation 写了 IaC 模板，方便重复部署（参考了这个视频）
  • 做了 demo 并整理成调研文档给团队

结果：Q Business 当时刚发布不久，功能还比较基础，最终作为一次可行性调研结束，结论和 demo 留给团队参考。

技术栈：AWS Q Business、CloudFormation、Jira、Confluence、Slack

GitHub Actions 依赖检查

问题：多个前端项目的依赖版本不一致，需要一个自动化的检查。

做法

  • 写 Shell 脚本检查package.json里的依赖版本是否一致
  • 把检查流程集成到公司的 GitHub Actions 公共仓库里

结果：后续新项目可以直接复用这个检查流程，不用每个项目各写一份。

技术栈：GitHub Actions、Shell
