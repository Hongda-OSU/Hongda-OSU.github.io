AWS AIF-C01

AWS 基础

Cloud Computing

  • Cloud computing 是通过云服务平台按需提供计算、数据库存储、应用程序和其他 IT 资源，按 pay-as-you-go 计费，需要什么类型、多大规模就用多少。

Deployment Models

  • Private Cloud：单个组织使用的云服务，不对外公开
  • Public Cloud：由第三方云服务商拥有和运营，通过互联网提供
  • Hybrid Cloud：部分服务器留在本地，部分能力扩展到云端

Types of Cloud Computing

  • IaaS（Infrastructure as a Service）：提供基础设施，如 EC2
  • PaaS（Platform as a Service）：提供平台，部署应用不用管服务器
  • SaaS（Software as a Service）：直接使用现成的软件

AWS Regions

  • AWS 在全球都有 Region，大多数 AWS 服务都是 region-scoped。

Availability Zones

  • 每个 Region 有多个 Availability Zone（通常 3 个，最少 3 个，最多 6 个）。每个 AZ 是一个或多个独立的数据中心，有冗余的电源、网络和连接。

Points of Presence

  • AWS 在 50+ 个国家、100+ 个城市有 750+ 个 Points of Presence，另有 15 个 Regional Edge Caches，用来以更低的延迟向用户交付内容。

生成式 AI 与 Amazon Bedrock

什么是生成式 AI

  • Generative AI 是 Deep Learning 的一个子集，用来生成与训练数据相似的新内容：文字、图片、音频、视频、代码等。
  • 它从训练数据里学到特征以及特征之间的关系（比如猫的耳朵形状、眼睛、尾巴、毛色），所以能生成训练集里从没出现过的新图像。

Foundation Model

  • Foundation Model（FM）是在海量、多样的数据上预训练的大模型，预训练好之后可以适配到很多下游任务。
  • 预训练用的是自监督学习：模型从无标签数据本身构造训练目标（比如预测下一个 token），不需要人工标注，所以能在海量数据上训练。
  • 考试问 Foundation Model 的训练方式，答案就是 self-supervised learning。

Large Language Models（LLM）

  • LLM 是专门处理文本的 Foundation Model，能生成连贯、像人写的文字。
  • 题目问在 AWS 上用 LLM 的产品，选 Amazon Bedrock 或 Amazon SageMaker JumpStart。

Generative Language Models

  • 我们通过 prompt 和 LLM 交互，模型利用学到的知识生成新内容。
  • LLM 是 non-deterministic 的：同一个 prompt 问两次，回答可能不一样。

传统机器学习模型也分几类：Deterministic，相同输入永远得到相同输出（如决策树）；Probabilistic，输出概率分布（如贝叶斯网络）；也有两者兼具的（如神经网络、随机森林）。

Amazon Bedrock

Amazon Bedrock 是用来构建生成式 AI 应用的全托管服务。

  • 用统一的 API 调用多家厂商的 Foundation Model
  • 无需管理服务器，按使用量付费
  • 数据留在你的账户里：Bedrock 不会用你的 prompt 和数据训练基础模型
  • 内置 Knowledge Bases（RAG）、Agents、Guardrails、模型评估等能力

如何选择基础模型

  • 模型类型、性能要求、能力、限制、合规要求
  • 可定制程度、模型大小、推理方式、许可协议、上下文窗口、延迟
  • 是否需要多模态

Multimodal Model（多模态模型）可以接受多种类型的输入（文本、图像、音频），也能生成多种类型的输出。比如给一段文字描述，生成对应的图片。

  • 多模态 embedding 模型能同时理解文本和图像，转成向量存进向量库，用户搜索时按相似度匹配最相关的结果。

Amazon Titan 与 Amazon Nova

  • Amazon Titan 是 AWS 自家的 Foundation Model 系列，通过全托管 API 提供文本、图像、embedding 等模型，题目里常见的是 Titan Embeddings。
  • AWS 现在主推的自家模型是 Amazon Nova 系列（文本、多模态、图像、视频）。
  • 一般来说，小模型更便宜。

模型定制：微调与持续预训练

Fine-tuning

  • 用你自己的数据训练基础模型的一个副本，得到定制模型
  • Fine-tuning 会改变模型的 weights
  • Fine-tuning 用的是 labeled data，是监督学习
  • 定制模型通常要购买 Provisioned Throughput 才能调用，适合负载稳定、可预测的场景；部分模型的定制版本现在也支持按需推理，以 Bedrock 文档为准

Instruction-based Fine-tuning

  • 提升预训练模型在特定领域、特定任务上的表现
  • 使用 labeled examples，也就是 prompt-response 对

Continued Pre-training

  • 用某个领域的 unlabeled data 继续训练基础模型，让它熟悉行业术语和知识，也叫 domain adaptation
  • 记住：Continued Pre-training 用的是 unlabeled data

Single-Turn Messaging

  • 指令微调的一种数据格式：system 加一组 user / assistant 消息

Multi-Turn Messaging

  • 为多轮对话场景做指令微调，user 和 assistant 交替出现

Transfer Learning

  • 把在一个任务上预训练好的模型迁移到相关的新任务，复用已有知识，减少对数据和算力的需求。微调就是迁移学习的一种具体方式。

评估基础模型

Automatic Evaluation

  • 先选任务类型（摘要、问答、文本分类、开放式生成等），再选内置或自定义的 prompt 数据集
  • 由算法指标或另一个评判模型（LLM-as-a-judge）自动给回答打分
  • 一些 benchmark 数据集可以快速检测偏见和潜在的歧视问题

Human Evaluation

  • 选一个工作团队（员工或领域专家），按评分标准审阅模型的回答

Automated Metrics

  • ROUGE：评估文本摘要，看生成内容和参考答案的重合度
  • BLEU：评估机器翻译的标准指标
  • BERTScore：比较语义相似度，比字面重合更深入
  • Perplexity：模型预测下一个 token 的能力，越低越好
  • Accuracy：适合分类任务，不适合评估翻译或摘要

Model Evaluation on Bedrock

  • 在同一份测试集上评估、比较多个基础模型，结合质量、成本和延迟，选出最适合你场景的模型。

RAG 与 Knowledge Bases

RAG（Retrieval-Augmented Generation）

  • 让基础模型可以引用训练数据之外的数据源：先检索相关资料，再连同问题一起交给模型生成回答
  • 不用改模型本身，资料更新后回答也能跟着更新

AWS 上的向量存储

  • Amazon OpenSearch Service（Serverless 和托管集群）：搜索与分析数据库，支持实时相似度查询、存储数百万条向量、快速的 kNN 搜索
  • Amazon Aurora PostgreSQL：关系型数据库，通过 pgvector 存储向量
  • Amazon Neptune Analytics：图数据库，支持图分析和 GraphRAG
  • Amazon S3 Vectors：成本低、持久，查询在亚秒级

数据源与使用场景

  • 数据源：Amazon S3、Confluence、Microsoft SharePoint、Salesforce、网页等
  • 客服机器人：产品功能、规格、故障排除指南、FAQ
  • 法律研究：法律法规、判例、法律意见
  • 医疗问答：疾病、治疗方案、临床指南、研究论文

GenAI 基本概念

Token 与 Tokenization

  • Token 是模型处理的最小单位，可以是一个词、词缀（如 “-ed”）、标点或短语
  • Tokenization 是把原始文本切成 token 序列

Context Window

  • LLM 生成时能考虑的 token 数量上限，输入和输出共享这个上限
  • 选模型时首先要看的因素之一

Embeddings

  • 把内容转成数字向量，用来比较相似度：文本对文本、图片对图片，或者文本对图片
  • Embedding 模型是搜索和 RAG 的基础

Bedrock Guardrails

  • 控制用户和基础模型之间的交互，同时检查输入和输出
  • 过滤有害内容、拦截受限话题
  • 屏蔽或移除 PII（个人身份信息）
  • 可以做上下文 grounding 检查，减少幻觉
  • 可以创建多个 Guardrails，并监控、分析违规的输入

Bedrock Agents

Bedrock Agents 现在叫 Bedrock Agents Classic，从 2026-07-30 起不再接受新客户，已有客户可以继续使用；新项目 AWS 推荐用 Amazon Bedrock AgentCore。考试题里仍以 Agents 和 action groups 的说法为主。

  • Agent 能理解用户的请求，把多步骤任务拆开，调用 API（action groups）和知识库来完成，比如查订单、订机票、处理工单
  • 每个 Agent 配置好可以执行哪些 action groups，以及能查哪些知识库

监控：Model Invocation Logging

  • Model Invocation Logging：记录每次调用的请求、响应和元数据，发送到 Amazon CloudWatch Logs 或 S3，方便监控、审计和排查问题。默认关闭，需要手动开启。
  • CloudWatch Metrics：Bedrock 的运行指标发布到 CloudWatch，可以配置告警。

Bedrock 计费

  • On-Demand
    • Pay-as-you-go，没有承诺
    • 文本模型按输入和输出的 token 收费
    • Embedding 模型按输入的 token 收费
    • 图像模型按生成的图片收费
    • 主要用于基础模型
  • Batch
    • 一次提交多个请求，结果写到 S3
    • 最多可便宜 50%
  • Provisioned Throughput
    • 按 model units 购买吞吐量，可以无承诺按小时计费，也可以承诺 1 个月或 6 个月
    • 吞吐量指每分钟最多处理的输入和输出 token
    • 支持基础模型和定制模型

改进模型的方式，按成本从低到高

  1. Prompt Engineering（$）：不需要训练模型，没有额外计算
  2. RAG（$$）：用外部知识，模型不需要什么都知道，也不用改模型
  3. Instruction-based Fine-tuning（$$$）：用指令数据微调，需要额外计算
  4. Continued Pre-training / Domain Adaptation（$$$$）：用大量领域数据继续训练，计算量最大

省钱要点

  • On-Demand：适合不可预测的负载，没有长期承诺
  • Batch：最多便宜 50%
  • Provisioned Throughput：通常不是为了省钱，而是为了预留容量
  • Temperature、Top K、Top P：对价格没有影响
  • 模型大小：一般小模型更便宜（因厂商而异）
  • 输入和输出的 token 数量：成本的主要来源

Prompt Engineering

什么是 Prompt Engineering

Prompt Engineering 是设计和优化 prompt，让基础模型的输出更符合你的需要。一个改进过的 prompt 通常包含：

  • Instructions：要模型完成的任务，以及怎么完成
  • Context：引导模型的外部信息
  • Input data：需要处理的输入
  • Output Indicator：输出的类型或格式

Negative Prompting

明确告诉模型回答里不要包含什么、不要做什么。

  • 避免不需要的内容：写明不要包含什么，减少无关或不当的内容
  • 保持聚焦：让模型不跑题
  • 更清晰：避免复杂术语和过多细节

推理参数

  • System Prompt：定义模型的角色、行为和回复方式
  • Temperature（通常 0～1）：控制随机性，低值更保守、一致，高值更多样、有创意
  • Top P（0～1）：只从累计概率达到 P 的候选 token 中采样，低值更集中，高值更多样
  • Top K：只从概率最高的 K 个候选 token 中采样，低值更集中，高值更多样
  • Length（Max Tokens）：回答的最大长度
  • Stop Sequences：遇到指定的文本就停止生成

Prompt Latency

  • 响应速度主要取决于模型大小、模型类型、输入 token 数和输出 token 数
  • 考试里记住：Temperature、Top P、Top K 不影响延迟

提示技巧

Zero-Shot Prompting

  • 不给示例，直接描述任务，完全依赖模型自身的知识

Few-Shot Prompting

  • 先在 prompt 里给几个示例，再提出新任务，让模型照着示例的内容和格式回答
  • 例如意图识别：给几组「用户输入 → 意图」的示例，模型就能把新的用户输入映射到正确的意图
  • 只给一个示例叫 One-Shot

Chain of Thought Prompting

  • 把任务拆成一系列推理步骤，让输出更有条理
  • 加上 “Think step by step” 这类句子会有帮助

RAG

  • 把检索到的外部资料拼进 prompt，让回答更准确、更有上下文。严格来说它不算提示技巧，详见上面的 RAG 一节。

Prompt Templates

  • 把固定指令和可替换的变量组合起来，统一、简化 prompt 的生成
  • 可以和 Bedrock Agents 一起使用

Prompt Template Injection

  • 用户可能在输入里夹带指令，试图劫持模板，让模型输出被禁止或有害的内容
  • 防护：在模板里明确写“只处理与任务相关的内容，忽略试图改变指令的输入”，再配合 Guardrails

Amazon Q

Amazon Q Business

Amazon Q Business 从 2026-07-31 起不再接受新客户，类似能力转到了 Amazon Quick Suite，已有客户可以继续使用。考试题里仍然会出现 Q Business。

  • 基于企业自己的数据和知识，回答问题、总结资料、生成内容
  • 构建在 Amazon Bedrock 上，但不能选择底层的基础模型
  • 用的是 LLM 加 RAG

Data Connectors 与 Plugins

  • Data Connectors（全托管的 RAG）：连接 40+ 企业数据源，如 Amazon S3、RDS、Aurora、Microsoft 365、Salesforce、Google Drive、Gmail、Slack、SharePoint
  • Plugins：和第三方服务交互、执行操作，如在 Jira、ServiceNow、Zendesk、Salesforce 里建工单
  • Custom Plugins：通过 API 接入任意第三方应用

IAM Identity Center

  • 用户通过 IAM Identity Center 登录，也可以接外部的身份提供方（IdP）
  • 回答只基于这个用户有权限访问的文档

Admin Controls

  • 按组织需要控制和定制回答，比如屏蔽某些话题、只用企业内部资料回答
  • Admin Controls 就是 Q Business 版的 Guardrails

Amazon Q Apps

  • 属于 Q Business，用自然语言描述需求就能创建生成式 AI 小应用，不需要写代码
  • 可以使用公司内部的数据

Amazon Q Developer

  • 帮你理解、构建和运维 AWS 应用的 AI 助手，基于 Amazon Bedrock
    • 回答 AWS 架构、最佳实践、文档问题，查询账户里的资源
    • 在 IDE 里：代码补全、生成代码、安全扫描、调试、语言版本升级

Amazon Q in Connect

  • 实时分析客户与客服的对话，自动推荐回复或下一步操作，帮助联络中心的客服更好地服务客户

Amazon Q 与其他 AWS 服务

Amazon Q in QuickSight

  • QuickSight 用于数据可视化和制作 dashboard，现在归在 Amazon Quick Suite 下面
  • 可以用自然语言对数据提问、生成 dashboard 和数据摘要

Amazon Q for EC2

  • 描述新的工作负载，Amazon Q 推荐最合适的 EC2 实例类型

Amazon Q Developer in chat applications

  • 原名 AWS Chatbot，在 Slack 或 Microsoft Teams 里接入你的 AWS 账户
  • 在聊天里问 AWS 问题、查看告警、排查问题

Amazon Q for Glue

  • AWS Glue 是 ETL（Extract, Transform, Load）服务，用于数据集成
  • Amazon Q 可以回答 Glue 相关问题、给出文档链接、生成数据集成代码、排查 Glue job 的报错

AI 与机器学习基础

AI、ML、DL 与 GenAI

什么是 AI

  • AI 是一个很宽的领域，目标是让系统完成通常需要人类智能的任务：感知、推理、学习、解决问题、决策

AI 的组成

  • Data Layer：收集大量数据
  • ML Framework and Algorithm Layer：数据科学家和工程师一起理解场景和需求，选择合适的框架和算法
  • Model Layer：设计模型结构、设置参数、损失函数和优化器，并完成训练
  • Application Layer：部署模型，把能力提供给用户

什么是 Machine Learning

  • ML 是 AI 的一个分支：在大量数据上训练算法，让它识别规律，再对新数据做预测或决策
  • 不需要人工逐条编写判断规则

什么是 Deep Learning

  • 用多层人工神经网络学习数据中的复杂模式
  • 能处理比传统 ML 更复杂的数据，如图像、语音、文本

什么是 Generative AI

  • 现代生成式 AI 通常基于深度神经网络，核心是预训练好的多用途基础模型

Transformer

  • 整句并行处理，而不是逐词处理，训练更快、更高效
  • Self-Attention：衡量句子里每个词对其他词的重要性，捕捉长距离依赖
  • Positional Encoding：给每个词加上位置信息
  • Encoder-Decoder 结构：BERT 只用编码器，GPT 只用解码器

ML Terms

  • GPT（Generative Pre-trained Transformer）：根据 prompt 生成文本或代码
  • BERT（Bidirectional Encoder Representations from Transformers）：双向读取文本，擅长文本理解
  • RNN（Recurrent Neural Network）：处理序列数据，如语音识别、时间序列预测
  • CNN（Convolutional Neural Network）：用卷积层学习空间特征，最适合图像识别和分类
  • ResNet（Residual Network）：很深的 CNN，用于图像识别、目标检测、人脸识别
  • SVM（Support Vector Machine）：用于分类和回归的经典算法
  • WaveNet：生成原始音频波形，用于语音合成
  • GAN（Generative Adversarial Network）：生成器和判别器对抗训练，生成合成的图像、视频或声音，可用于数据增强
  • XGBoost（Extreme Gradient Boosting）：梯度提升的一种高效实现，常用于表格数据

图像分类题选 CNN（或 ResNet）。RNN 用于序列数据，GAN 用于生成而不是分类，RAG 和图像分类无关。

训练数据

Labeled vs. Unlabeled Data

  • Labeled Data：有输入特征，也有对应的输出标签，用于监督学习
  • Unlabeled Data：只有输入特征，没有标签，用于无监督学习

Structured Data

  • 按固定字段组织，通常是行和列
  • Tabular Data：表格，行是记录，列是特征
  • Time Series Data：按时间顺序记录的数据点

Unstructured Data

  • 没有统一的字段结构，通常是文本或多媒体
  • Text Data：文章、社交媒体帖子、客户评论等
  • Image Data：格式和内容都很多样

Supervised Learning

  • 用 labeled data 训练，学习输入到输出的映射，再预测新数据
  • 效果好，但标注数据需要时间和成本，数据量很大时难以全部标注
  • 例子：Linear Regression 预测房价（连续值）；神经网络识别手写数字

Regression

  • 预测数值，输出是连续的，可以是范围内的任何值

Classification

  • 预测类别标签，输出是离散的
  • 分二分类、多分类、多标签分类
  • 典型算法：k-NN（K-Nearest Neighbors），看离新样本最近的 K 个已标注邻居属于哪一类

Training、Validation 与 Test Set

  • Training set：训练模型
  • Validation set：调超参数、挑选模型（可选）
  • Test set：模型定下来之后，评估它在没见过的数据上的泛化能力，不参与调参

Feature Engineering

  • 用领域知识，把原始数据转换成对模型有用的特征，提升模型表现
  • 结构化数据：归一化、处理缺失值、类别编码，例如根据面积、位置、房间数预测房价
  • 非结构化数据：分词、向量化、特征提取，例如客户评论的情感分析

Unsupervised Learning

  • 在没有标签的数据里发现模式、结构或关系
  • 常用技术：Clustering、Association Rule Learning、Anomaly Detection，以及 Dimensionality Reduction（降维）
  • 好的特征工程同样能提升效果

Clustering

  • 按特征相似度把数据点分组，例如客户分群，再针对不同人群制定营销策略
  • 常用算法 K-Means：无监督，把数据分成 K 个簇，不需要标签。别和监督学习的 k-NN 搞混。

Association Rule Learning

  • 例子：购物篮分析，发现哪些商品经常一起被买，超市可以把它们放在一起

Anomaly Detection

  • 例子：欺诈检测，系统把可疑交易标记出来，交给人工调查

Semi-supervised Learning

  • 用少量 labeled data 加大量 unlabeled data 训练
  • 先用标注数据训练初始模型，再给未标注数据打伪标签，然后一起训练
  • 例子：文档分类

Self-Supervised Learning

  • 模型从数据本身构造训练目标（伪标签），不需要人工标注，比如遮住一个词让模型猜（BERT），或者预测下一个 token（GPT）
  • 广泛用于 NLP 和计算机视觉的预训练

Reinforcement Learning

  • Agent 在环境中执行动作，根据得到的奖励或惩罚调整策略，目标是让长期累计奖励最大

RLHF

  • RLHF = Reinforcement Learning from Human Feedback，用人类反馈让模型的回答更符合人的偏好
  • 常见流程：
    1. 用人工写的示范数据做监督微调
    2. 模型对同一个问题生成多个回答，由人类比较、排序
    3. 用这些偏好数据训练一个奖励模型（reward model）
    4. 用奖励模型打分，通过强化学习继续优化语言模型

Model Fit、Bias 与 Variance

Model Fit

  • Overfitting：训练数据上表现好，新数据上表现差。模型太复杂，记住了训练数据里的噪声，泛化能力弱。
  • Underfitting：训练数据上表现也差，模型太简单或特征不够。
  • Balanced：既不过拟合也不欠拟合。

欠拟合 = High Bias：模型太简单，训练和测试表现都差。
过拟合 = High Variance：模型太复杂，训练表现好但测试表现差，对训练数据过度敏感。

Bias

  • 统计上的 bias：模型的平均预测和真实值之间的系统性偏差
  • High Bias：模型连训练数据都拟合不好，属于欠拟合
  • 降低：用表达能力更强的模型、加入有用的特征

负责任 AI 里说的 bias 是另一回事，指模型对某些群体不公平。常见原因是训练数据不平衡或代表性不足；降低的方法是补充或增强代表性不足群体的数据、平衡数据集，再用 SageMaker Clarify 之类的工具检测。

Variance

  • 用分布相似、但不同的训练集训练时，模型表现的波动程度
  • High Variance：对训练数据的变化很敏感，属于过拟合
  • 降低：特征选择（更少但更重要的特征）、增加数据、正则化、交叉验证

模型评估指标

Confusion Matrix

混淆矩阵用于评估分类模型，通过 TP、TN、FP、FN 四个数字，看模型在各个类别上哪里表现好、哪里需要改进。

  • True Positive（TP）：预测为正，实际为正
  • True Negative（TN）：预测为负，实际为负
  • False Positive（FP）：预测为正，实际为负（误报）
  • False Negative（FN）：预测为负，实际为正（漏报）
  • Accuracy = (TP + TN) / Total
  • Precision = TP / (TP + FP)
  • Recall = TP / (TP + FN)

Precision：预测为正的里面，真正是正的比例，关注减少误报（FP）。
Recall：所有真正是正的里面，被找出来的比例，关注减少漏报（FN）。
F1-Score：Precision 和 Recall 的调和平均。类别不平衡时，准确率可能掩盖少数类的错误。

Regression Metrics

  • MAE（Mean Absolute Error）：误差绝对值的平均，和目标值同单位
  • MAPE（Mean Absolute Percentage Error）：用百分比衡量误差，真实值接近 0 时不适用
  • MSE（Mean Squared Error）：误差平方的平均，对大误差惩罚更重
  • RMSE（Root Mean Squared Error）：MSE 开根号，和目标值同单位
  • R²（R-Squared）：模型解释了数据中多少变化，越接近 1 越好

Inference

  • Inference 是用训练好的模型对新数据做预测
  • Real-time：数据到达就马上返回结果，看重低延迟
  • Batch：一次处理大量数据，看重吞吐量

Inference at the Edge

  • Edge device 靠近数据源，算力较弱，网络可能不稳定
  • 小语言模型（SLM）部署在边缘设备上：延迟低、可以离线
  • 大语言模型（LLM）部署在远程服务器上：能力强，但需要联网

机器学习项目流程

  • Define Business Goals：定义价值、预算、成功标准和 KPI
  • ML Problem Framing：把业务问题转换成 ML 问题，判断 ML 是否合适
  • Data Processing：数据收集、预处理、特征工程
  • Exploratory Data Analysis：建模前用统计摘要和图表（如相关矩阵）了解数据结构、发现规律和异常值
  • Model Development：训练、调参、评估，反复迭代
  • Deployment：选择部署方式（实时、批量、serverless 等）
  • Monitoring：监控模型表现，排查问题
  • Iterations：用新数据和反馈持续改进

Hyperparameter

  • Hyperparameter 是训练前由人设定、控制模型结构和学习过程的参数；模型参数（如权重）则是训练中学出来的
  • Hyperparameter tuning：调整学习率、正则化、dropout 等，防止过拟合，提升泛化能力

重要的超参数

  • Learning rate、Batch size、Number of Epochs、Regularization
  • 增加 epochs 能让模型学得更充分，但太多会过拟合，可以配合 early stopping

Overfitting

  • 训练数据上表现好，新数据上表现差
  • 原因：训练数据太少、训练太久、模型太复杂，学到了噪声
  • 解决：增加训练数据、Early stopping、Data augmentation、调整超参数

可解释性

Interpretability Trade-Offs

  • Interpretability：人能理解模型为什么做出某个决策的程度
  • Explainability：理解模型的整体行为和本质
  • 考试考的权衡：越透明、越好解释的模型（如线性模型、浅层决策树），性能往往越有限；越复杂的模型（如神经网络）性能更强，但更难解释。不过这不是绝对的，实际取决于数据和任务。

Partial Dependence Plots（PDP）

  • 展示单个特征变化时，模型的平均预测怎么变化
  • 对神经网络这类“黑盒”模型特别有用
  • 和 Shapley 值的区别：PDP 是全局解释，看某个特征在整个数据集上的影响趋势；Shapley 值是局部解释，量化每个特征对单次预测的贡献

Human-Centered Design（HCD）for Explainable AI

  • Design for amplified decision-making：在高压场景下减少风险和错误
  • Design for unbiased decision-making：让决策过程尽量没有偏见
  • Design for human and AI learning：认知学徒制、个性化、以用户为中心的设计

生成式 AI 的挑战

Toxicity

  • 生成冒犯性、令人不安或不当的内容
  • 缓解：整理训练数据，识别并移除冒犯性内容；运行时用 Guardrails 过滤

Hallucinations

  • 听起来正确、实际上是错的断言，比如编造的书名、来源或数字
  • 缓解：让用户知道要核实模型生成的内容；用 RAG 提供可靠资料，并对关键结论人工复核

Plagiarism and Cheating

  • 担心生成式 AI 被用来代写论文、求职材料等
  • 检测 AI 生成文本和图像的技术随之出现，但检测结果可能误判

Prompt Misuses

  • Poisoning：故意往训练数据里混入恶意或带偏见的数据
  • Hijacking / Prompt Injection：在 prompt 里嵌入指令，影响模型的输出
  • Exposure：训练或推理时暴露敏感信息的风险
  • Prompt Leaking：无意中泄露模型使用的 prompt 或输入
  • Jailbreaking：绕过模型的伦理和安全限制

  • 管理、优化和扩展组织的 AI 项目
  • 治理是建立信任的关键

  • Vulnerability Management：找出 AI 系统的漏洞，如软件 bug、模型弱点
  • Infrastructure Protection：保护云平台、边缘设备和数据存储

  • Prompt Injection：操纵输入的 prompt，让模型生成恶意或不良内容
  • Data Encryption：静态和传输中的数据都要加密

数据治理的两个概念

  • Data access control：控制谁能访问数据、能做什么操作（认证 + 授权）
  • Data integrity：确保数据准确、一致、没有被篡改

AWS Shared Responsibility Model

  • AWS 负责 Security of the Cloud（云本身的安全）
  • 客户负责 Security in the Cloud（云中的安全）：数据、身份与权限、应用配置、加密等

IAM

Users 与 Groups

  • Root Account：创建账户时默认生成，拥有全部权限，不要日常使用，也不要共享
  • Users：组织里的个人，可以属于多个组
  • Groups：只能包含用户，不能嵌套其他组
  • 人员访问优先用 IAM Identity Center 的联合身份和临时凭证

Permissions

  • 用策略定义用户、组或角色的访问权限
  • 最小权限原则（Least Privilege）：只授予完成任务所需的最小权限
  • 默认拒绝，显式拒绝优先于允许

Policies

  • 策略是 JSON 文档，Statement 主要包含：
    • Effect：Allow 或 Deny
    • Action：允许或拒绝的操作
    • Resource：作用于哪些资源
    • Condition：生效条件（可选）
    • Principal：谁可以访问。只在资源策略和角色信任策略里写，身份策略里不写
  • Version 是策略语言的版本（2012-10-17），不是创建日期
  • Inline Policy：直接附加到单个用户、组或角色上的策略

Roles

  • 让 AWS 服务通过临时凭证安全地访问其他资源，不用在代码里写长期密钥
  • 常见的角色：
    • EC2 Instance Role：让 EC2 实例访问其他 AWS 服务
    • Lambda 执行角色：授予 Lambda 函数执行权限
    • Service Role：让某个服务代你操作，如 CloudFormation

Amazon S3

Buckets

  • S3 是全局服务，但 bucket 创建在指定的 Region
  • 对象（文件）存放在 bucket 里
  • bucket 名称在同一个 AWS 分区内全局唯一

Objects

  • 每个对象有一个 key，就是它在 bucket 里的完整名称（prefix + 对象名）
  • 单个对象最大 5 TB，单次 PUT 上传最大 5 GB，更大的要用 Multipart Upload

重要特性

  • S3 是 serverless 服务，读写是强一致的
  • 对象所有权：新建 bucket 默认是 Bucket owner enforced，ACL 被禁用，bucket 里的对象都归 bucket 所有者
  • Lifecycle 规则可以按对象年龄、前缀、标签，自动把对象转到更便宜的存储类别

S3 Storage Classes

  • 常用的有 8 种：Standard、Intelligent-Tiering、Standard-IA、One Zone-IA、Glacier Instant Retrieval、Glacier Flexible Retrieval、Glacier Deep Archive，以及低延迟的 Express One Zone

S3 Standard

  • 频繁访问的数据，最常用
  • 高持久性（11 个 9）、高可用性（99.99%）、低延迟

S3 Infrequent Access

  • Standard-IA：至少 3 个可用区冗余，最低存储时长 30 天
  • One Zone-IA：只在单个可用区，更便宜，但可用区损毁时数据会丢失，适合可重建的数据

S3 Glacier

  • Instant Retrieval：毫秒级读取，最低存储 90 天
  • Flexible Retrieval：先恢复再读取，Expedited 1～5 分钟、Standard 3～5 小时、Bulk 5～12 小时，最低存储 90 天
  • Deep Archive：Standard 12 小时内、Bulk 48 小时内，最便宜，最低存储 180 天

S3 Intelligent-Tiering

  • 根据访问情况，自动在访问层之间移动对象
  • 按对象收取少量监控费，没有取回费，不需要手动管理

Amazon EC2

  • 属于 IaaS，实例运行在特定的可用区
  • 常和 EBS（块存储）、ELB（负载均衡）、Auto Scaling（扩缩容）一起使用

  • User Data：实例启动时自动运行的脚本，比如安装 Apache
    • 默认只在首次启动时运行
    • 默认以 root 用户执行

AWS Lambda

  • Serverless 函数计算，单次执行最长 15 分钟
  • 事件驱动：S3 事件、DynamoDB Streams、API Gateway 等都能触发；也可以用 EventBridge 定时触发
  • 按请求次数和执行时长计费，自动扩展，不用管理服务器

Lambda Limits

  • 内存 128 MB～10 GB，超时最长 15 分钟
  • 部署包：zip 压缩后 50 MB、解压后 250 MB，容器镜像 10 GB
  • 账户并发有配额，默认每个 Region 1,000，可以申请提高

Amazon Macie

  • 用 ML 和模式匹配，发现和分类 S3 里的敏感数据（如 PII）
  • 持续评估 S3 bucket 的安全和访问控制，发现结果可以通过 EventBridge 通知

AWS Config

  • 记录 AWS 资源的配置，以及配置随时间的变化
  • 例子：检查 ACM 证书是否快过期、安全组是否开放了不受限的 SSH

Config Rules

  • 用 AWS 托管规则或自定义规则（Lambda 或 Guard）检查资源是否合规
  • 常见规则：S3 bucket 是否公开、EC2 是否使用批准的 AMI、EBS 卷是否加密
  • 规则评估本身不会阻止部署

Config Remediations

  • 用 Systems Manager Automation 文档自动修复不合规的资源，比如自动关闭不受限的 SSH 访问

Config Notifications

  • 资源不合规时，用 EventBridge 触发通知或自动化，可以接 SNS、Lambda、SQS

CloudTrail 和 Config 的区别：CloudTrail 记录谁在什么时候做了什么（API 调用审计）；Config 记录资源的配置是什么、怎么变化（配置管理）。

Amazon Inspector

  • 自动化的漏洞评估服务，持续扫描漏洞，生成安全发现
  • 支持的资源：
    • EC2 实例：软件包漏洞和网络可达性
    • ECR 容器镜像：镜像里的系统和语言软件包漏洞
    • Lambda 函数：依赖包漏洞，代码扫描需另外开启

AWS CloudTrail

  • 账户的治理、合规和审计服务，记录账户里的 API 调用和事件
  • Event history 默认保留每个 Region 最近 90 天的管理事件；要长期保存，就创建 Trail 把日志交付到 S3
  • 资源被误删时，先查 CloudTrail

CloudTrail Events

  • Management Events：创建、删除、修改资源等控制面操作
  • Data Events：S3 对象级操作、Lambda 调用、DynamoDB 操作等数据面活动，需要单独开启
  • Insights Events：检测异常活动

CloudTrail Insights

  • 以正常活动为基线，发现异常的 API 调用频率和错误率，比如 API 调用突然激增

AWS Artifact

  • 按需获取 AWS 的合规报告和协议
  • Artifact Reports：SOC、PCI 报告和 ISO 认证资料
  • Artifact Agreements：查看、接受和管理协议，如 Business Associate Addendum（BAA）

AWS Audit Manager

Audit Manager 从 2026-04-30 起不再接受新客户，已进入维护模式，AWS 建议新项目改用 AWS Config Conformance Packs。

  • 评估 AWS 工作负载的风险和合规情况
  • 持续收集 AWS 使用情况作为审计证据，生成评估报告

AWS Trusted Advisor

  • 分析 AWS 账户，在 6 个类别给出最佳实践建议：Cost Optimization、Performance、Security、Fault Tolerance、Service Limits、Operational Excellence
  • 能用哪些检查取决于支持计划

Amazon VPC

  • VPC 是你在 AWS 里逻辑隔离的私有网络

Subnets

  • VPC 按 Region 创建，子网属于单个可用区
  • 公有子网：有到 Internet Gateway 的路由，可以直接访问互联网，如 Web 服务器
  • 私有子网：没有到 Internet Gateway 的直接路由，通过 NAT Gateway 访问外网，如数据库

Internet Gateway 与 NAT Gateway

  • Internet Gateway（IGW）：让公有子网的资源和互联网双向通信
  • NAT Gateway：让私有子网的资源主动访问互联网，但外部不能主动连进来

Security Group 与 NACL

  • Security Group：作用在网络接口（实例）上，只有允许规则，有状态
  • NACL：作用在子网上，有允许和拒绝规则，无状态，返回流量也要放行

VPC Flow Logs

  • 记录网络接口进出流量的元数据（不含数据包内容），用于监控和排查网络问题，可以发送到 CloudWatch Logs、S3 或 Amazon Data Firehose

VPC Peering

  • 把两个 VPC 私有连接起来，可以跨账户、跨 Region，两边的 CIDR 不能重叠
  • 不可传递：A 连 B、B 连 C，不代表 A 能连 C

VPC Endpoints

  • 私有访问 AWS 服务，流量不经过公网
  • Gateway Endpoint：用于 S3 和 DynamoDB，通过路由表实现
  • Interface Endpoint：基于 PrivateLink，在子网里创建一个带私有 IP 的网络接口

AWS PrivateLink

  • 私有地发布和访问服务：服务提供方用 Network Load Balancer 发布，使用方在自己的 VPC 里创建 Interface Endpoint 连接
  • 流量不经过公网，也不需要 VPC Peering，是向其他 VPC 暴露服务最安全的方式

Site-to-Site VPN 与 Direct Connect

  • Site-to-Site VPN
    • 通过公网建立 IPsec 加密隧道，连接本地网络和 AWS VPC
    • 组件：AWS 端的 Virtual Private Gateway（或 Transit Gateway）加本地的 Customer Gateway
  • Direct Connect
    • 从本地到 AWS 的专用物理连接，不走公网
    • 比 VPN 更稳定、带宽更高，但开通更慢、成本更高
    • 默认不加密，需要加密时可以叠加 VPN 或使用 MACsec

AWS Client VPN

  • 托管的 VPN 服务，基于 OpenVPN，让远程用户从任何地方安全连接到 AWS 和本地网络，适合远程办公

AWS Transit Gateway

  • 区域级的网络中心，用中心辐射式的结构把多个 VPC、VPN 和 Direct Connect 连在一起，替代大量点对点的 Peering
  • 用路由表控制网络之间的转发和隔离
